# Оптимизация и мониторинг

Границы GeoJSON загружаются с текущего сайта один раз. Слои регионов сохраняются;
стиль обновляется только при изменении статуса. Маркеры аэропортов обновляются по коду,
без пересоздания всей группы. Всплывающие окна получают свежие данные при открытии.
Один цикл опроса раз в 30 секунд после завершения запросов, таймаут 10 секунд.
Скрытые вкладки и офлайн не запускают новые запросы; возврат запускает обновление.
Пуш-уведомления service worker продолжают работать независимо от опроса страницы.

В карточке Крымского моста доступны источник, время сообщения, ручное обновление
и выбор производительности. Авто включает экономный режим при <=4 логических ядрах,
<=4 ГБ памяти, Save-Data или prefers-reduced-motion. Выбор сохраняется локально.
Экономный режим отключает размытие, CSS-анимации и анимацию масштаба карты.

## Развёртывание

Обновить index.html вместе с обоими существующими geojson в той же директории.
На бэкенд добавить bridge.py рядом с server.py и перезапустить сервер.
Проксировать GET /api/bridge так же, как /api/statuses и /api/airports.
Монитор использует существующий Telegram-клиент и публичный most_official;
дополнительные ключи и библиотеки для него не нужны.
Источник: https://mintrans.gov.ru/activities/324/330 (ссылка на most_official).

Статус относится только к автодвижению и отражает явное сообщение источника.
Очереди не считаются доказательством открытия. Через 6 часов сообщение устаревает;
через 3 минуты без успешного опроса источник считается недоступным.
При задержках Telegram и переходе источника в MAX интерфейс покажет отсутствие
актуальных данных. Ссылка на источник остаётся доступной. Статус не сохраняется
между перезапусками: начальный опрос читает последние 100 сообщений.

## Точки БПЛА на карте

Фронтенд опрашивает GET /api/drones вместе с остальными эндпоинтами (тот же цикл
30 секунд) и рисует отдельные маркеры фиксаций БПЛА поверх слоя регионов —
кружок с иконкой, всплывающее окно с населённым пунктом, регионом, количеством
(«не менее N», «группа БПЛА» и т.п.), выдержкой из сообщения, источником и
временем. Кнопка «БПЛА на карте» включает/выключает слой, выбор сохраняется
в localStorage. Показываются только фиксации с известными координатами
(location != null); нерезолвленные попадают в snapshot.unresolved и на карте
не отображаются, чтобы не придумывать положение.

На бэкенде это стало возможным только после добавления data/places.json —
файла газеттира для drones.py Gazetteer, которого раньше не было в репозитории
(только сырые дампы GeoNames data/RU.zip и data/UA.zip лежали неиспользуемыми).
Без него Gazetteer.resolve() всегда возвращал None, и location у всех фиксаций
был пустым. data/build_places.py собирает регионы (полные ADM1-регионы РФ и
приграничные/оккупированные области Украины с русскими самоназваниями вроде
«ДНР», «ЛНР», «Крым») и ~16.6k населённых пунктов с кириллическими алиасами
из RU.txt/UA.txt, с дедупликацией дублирующихся строк GeoNames для одного и
того же места (одинаковый алиас + <6 км друг от друга сливаются в одну запись,
иначе resolve() из-за неоднозначности двух id возвращал None даже для крупных
городов вроде Шебекино). Пересобрать: `cd data && unzip -o RU.zip -d RU &&
unzip -o UA.zip -d UA && python3 build_places.py && mv places.json ..`.

## Проверка

python -B -m unittest discover -s Radar-backend -p test_bridge.py -v

В браузере: проверить панорамирование/масштаб, смену языка, линейку, аэропорты,
открытый popup после обновления; вкладки Network/Performance при неизменных данных.
Проверить offline, возврат из фона, HTTP 500, экономный режим, ширину 360 px.
